# 完整备份与恢复

当前格式为 `CET6CompleteBackup` v1 ZIP，学习字段仍为 JSON v5 / Room v8，旧学习 JSON v1—v5 可继续预览与合并恢复。

在「我的 → 备份与恢复」导出完整 ZIP。它包含所有学习记录、未提交草稿、讲解与对话、FSRS 状态、每日目标，以及尚未作答的个人题库。恢复预览同时显示训练、对话与题库数量；旧 JSON 会明确提示题库缺失。登录凭证、API Key、原卷 PDF、计时器及界面偏好不进入备份。

ZIP 按表与题库分段，清单记录每段的字节数、SHA-256、总记录数；缺段、未知条目、重复标识、错误引用或校验不符会在写入前拒绝。普通 JSON 保留 32 MiB 读取限制，ZIP 的学习记录可跨段超过该限制；已用 570 条各 60,000 字符的回复（大于 32 MiB）验证往返。ZIP 单段最多 2 MiB、总解压最多 512 MiB、条目少于 10,000，原有表记录数上限继续有效。仍需在内存中组装 Room 快照与解析结果，不能把 512 MiB 安全读取上限当作手机内存容量承诺。

恢复先检查合并冲突，再将恢复内容和“采用每日目标”选项原子保存在应用私有目录，并读回验证；任务完整落盘后才修改数据库。在 Room 事务中合并学习记录后，题库用 AtomicFile 保存并读回核对；两部分均成功后才清除任务。题库为空或合并结果未变时不重写文件。旧学习 JSON 不读取或改写个人题库，即使本机题库损坏也可独立恢复学习记录。

两个存储仍不是跨文件事务，而是可继续执行的恢复任务。若中断，重启会先继续任务，再开放学习界面；恢复失败则保留任务，允许读取已有离线记录，在备份页“继续上次恢复”。本机记录与备份冲突时拒绝覆盖，损坏任务也不会自动丢弃；持续失败需保留原备份和本机数据后联系维护者，不能把部分写入当作完整恢复。恢复任务需要额外本机空间，原 ZIP 仍需独立保留。恢复后核对题库数量、原稿和最近对话，再继续学习。

2026-10-24 已验证：空题库、旧 JSON、数据库失败回滚、数据库已提交而题库保存失败后的重试、重复导入、冲突与损坏任务保留。模拟器在任务保留后实际强停，新进程补齐题库且不重复历史；另用实际 Activity/ViewModel 启动验证自动继续任务、草稿与既有题库哈希保留。见 [恢复验证证据](../test-evidence/restore-recovery-20261024.json)。不将这些演练等同于掉电、真实存储损坏或所有低内存情形。

明文 ZIP 不提供加密或来源签名，SHA-256 用于检测意外缺失与损坏。选择可信保存位置，并独立保存原卷；不要把本机单一文件或 Git 仓库当作唯一备份。私人资料保留规则见 [DATA_RETENTION.md](DATA_RETENTION.md)。


2026-10-25 增补：ZIP 清单与学习 JSON 现在复用严格字段读取。版本、生成时间、题库/表计数、分段字节数必须是范围有效的 JSON 整数，不接受数字字符串、小数或溢出后绕回的数值；格式名、条目名及哈希必须是文本。既有 ZIP v1 与旧 JSON 格式版本保持不变。35 个异常清单在 JVM/Android 双端拒绝，完整解码到恢复的隔离检查确认：本机学习快照和题库字节未变，未创建恢复任务。149 项 JVM 和完整隔离套件通过，Lint 0 错误 / 7 个既有警告。证据：[backend-backup-manifest-20261025.json](../test-evidence/backend-backup-manifest-20261025.json)。

## 启动恢复与草稿同步（2026-10-27）

新增断点检查复现：恢复任务已保存、Room 尚未提交时结束进程，重启后数据库虽然恢复成功，编辑器仍持有恢复前的草稿。此前 2026-10-24 的真实启动证据来自数据库已提交的断点，未覆盖此阶段。

修复后，仅在启动时存在恢复任务的情况下，`CoachState` 等待启动恢复结束再查询三类当前草稿；自动启动恢复也不再提前回写内存草稿。日常手动恢复仍先 flush 当前编辑。没有数据库迁移、备份格式或依赖变化；恢复失败时也会结束等待，允许读取原有本地稿，任务继续保留。

模拟器验证了三个独立的新进程路径：

| 中断/启动方式 | 实际核对 |
| --- | --- |
| 任务已落盘、数据库未提交，正常启动 | 三类恢复稿进入编辑器；再次 flush 不新增空练习，旧练习与题库哈希保留 |
| 数据库已提交、任务尚未清除，正常启动 | 续传完成，恢复记录及全部旧练习、题库哈希保留 |
| 任务已落盘、数据库未提交，系统 ACTION_SEND 启动 | 写作/翻译恢复稿进入编辑器，阅读原稿保留，新分享作为独立练习；记录 ID 集合与哈希一致 |

新增场景仅允许模拟器。先运行 `-e scenario restore-startup-pending-prepare` 并等到 `PREPARED`；它会保持准备进程存活。在另一终端对**同一模拟器**执行 `am force-stop com.example.cet6`，再运行 `-e scenario restore-startup-resume`（分享路径用 `restore-startup-share-resume`）。数据库已提交的准备入口仍为 `restore-startup-prepare`。这些命令均使用 `com.example.cet6.test/com.example.cet6.LocalDataInstrumentation`；不要在手机或正在使用的训练会话运行。准备进程在主动结束后报告 `Process crashed` 是该断点的预期结果，最终续传场景必须单独返回 `PASS`。

完整隔离套件、正常 ViewModel 生命周期与 149 项 JVM 通过，Lint 0 错误 / 7 个既有警告。见 [backend-restore-draft-20261027.json](../test-evidence/backend-restore-draft-20261027.json)。这仍不等于真实手机恢复、LMKD 或掉电验证。

## 恢复任务首次落盘失败（2026-10-28）

新增隔离文件系统故障：在唯一测试目录中阻塞 AtomicFile 的 `.new` 暂存路径，恢复任务无法创建时，核对已有学习快照、题库字节完全不变，且没有错误报告存在已落盘任务。解除测试故障后同份备份恢复成功、无重复记录。此检查已纳入 `restore-recovery` 和默认完整隔离套件。它验证真实文件操作失败，不代表真实磁盘满、硬件损坏或掉电已验收。
