## 真实登录与推理结果

用户随后在手机完成了系统浏览器登录与授权。应用显示已验证身份及套餐 scope，成功获取 7 个账号可见模型，选中 `GPT-6.1-Sol`。没有记录账号邮箱、令牌或完整授权 URL。

第一次发送预置短消息时，客户端因 MIME 检查失败而拒绝响应。诊断版读到 HTTP 200、无法解析出的 Content-Type、SSE 正文及首个 `response.created` 事件。无法据此断定响应头是服务端省略还是中间链路改变。

增加仅对缺失 Content-Type 的严格兼容：首个完整事件必须是 `response.created`，内嵌对象必须为 `response`；错误 MIME、无效 JSON、无关 SSE 和缺少 `response.completed` 的流不会判为成功。未改动 OAuth 端点或授权参数。

覆盖安装修复版后再次发送同一预置消息：

- 请求：「请只回答：六级研习室 API 测试成功。」
- 应用状态：「API 测试成功：已收到 response.completed。」
- 模型回答：「六级研习室 API 测试成功。」

这证明该设备、该账号及该模型在本次测试中完成了一次真实套餐路由请求，不代表所有账号、模型或后续用量始终可用。

两次覆盖安装并冷启动后均无需重新登录，模型目录可重新加载，验证了本次凭证的 Keystore 加密保存与恢复。当前应用进程所查日志未匹配到崩溃或 ANR。

当前构建及 26 项 JVM 测试通过，Lint 为 0 错误、7 警告；签名和 ZIP 对齐检查通过。脱敏结果见 `test-evidence/phone-connection-result.txt`。
